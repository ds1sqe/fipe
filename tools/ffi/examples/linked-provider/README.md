# Explicit linked scalar providers

This author example links one C object and a separate Rust provider crate into a
small VM host. It selects either implementation explicitly; both implement
`proof.ops` from the same `api.fipi`. It does not discover or load libraries.
This example passed its serial test and both runs on Rust 1.98.1 with a C11
compiler on x86_64 GNU Linux using explicit immutable source patches. The adapter
archive contains all example assets, including the generated lock. A fresh
external archive dependency rehearsal remains separate; no registry availability
is assumed.

The three operations echo `Integer`, echo `String`, and return a Host failure.
The host reads a selected interface once, compares its module and exact bytes to
the linked descriptor, then registers into fresh declarations. Whitespace, comments
and line endings are part of this scalar pairing. A mismatch stops before callback;
matching bytes do not grant permission or authenticate code. Each actual call
still needs Host authorization and its reply goes through `Machine::reply`.

## Copy before building

Cargo excludes nested packages from an outer package archive. These two manifests
therefore ship as `.in` files. Copy this entire directory to an external working
directory, then materialize them there. Do not create `Cargo.toml` inside the
adapter source tree before packaging it.

```sh
cp Cargo.toml.in Cargo.toml
cp rust-provider/Cargo.toml.in rust-provider/Cargo.toml
```

The templates pin `fipe` and `fipe-ffi` to `=0.2.0-dev.3`. No registry availability
is assumed. Prepublication verification supplies both dependencies through an
explicit task-local Cargo patch configuration. For example, with absolute paths to
approved extracted packages:

```toml
# Save outside the package as /absolute/task/artifact-patches.toml.
[patch.crates-io]
fipe = { path = "/absolute/artifacts/fipe-0.2.0-dev.3" }
fipe-ffi = { path = "/absolute/artifacts/fipe-ffi-0.2.0-dev.3" }
```

For a maintainer's source-only check these paths may instead select the approved
immutable source snapshot and its `tools/ffi`; that does not prove an installed
artifact works. Never silently fall back to a live checkout during archive rehearsal.
The final release workflow updates both pins and regenerates the example lock.

## Header and toolchain

This example requires Rust 1.98.1, a C11 `cc` accepting GCC-style flags, and the
same `x86_64-unknown-linux-gnu` host/target. No cross or other-platform support is
claimed. Set `FIPE_FFI_INCLUDE` to the absolute directory containing `fipe.h` from
the matching adapter package: `/absolute/artifacts/fipe-ffi-0.2.0-dev.3/include`.
A source-only maintainer check may use the approved snapshot's `tools/ffi/include`.
The build never searches a registry directory or downloads a header.

`build.rs` embeds `api.fipi` as C bytes in its output directory; the Rust provider
includes that same file. It compiles C for both the executable and its unit test.
It never regenerates or edits the interface file.

## Run and check

The included `Cargo.lock` was generated by Cargo for the current exact pins and
its bytes were checked in the adapter archive. To regenerate it after an approved
pin or selected dependency change, resolve only the selected graph offline in the
copied working directory, then retain the generated lock:

```sh
cargo +1.98.1 generate-lockfile --offline --config /absolute/task/artifact-patches.toml
```

An absent cache/dependency is an explicit prerequisite failure, not permission to
fetch a different version. After resolution, use a task-private target and build
directory for the test and both implementations:

```sh
export FIPE_FFI_INCLUDE=/absolute/artifacts/fipe-ffi-0.2.0-dev.3/include
cargo +1.98.1 test --locked --offline -j 8 --config /absolute/task/artifact-patches.toml --target-dir /absolute/task/target --config 'build.build-dir="/absolute/task/build"'
cargo +1.98.1 run --locked --offline -j 8 --config /absolute/task/artifact-patches.toml --target-dir /absolute/task/target --config 'build.build-dir="/absolute/task/build"' -- c /absolute/copied-example/api.fipi
cargo +1.98.1 run --locked --offline -j 8 --config /absolute/task/artifact-patches.toml --target-dir /absolute/task/target --config 'build.build-dir="/absolute/task/build"' -- rust /absolute/copied-example/api.fipi
```

Both runs should print:

```text
42
hello
```

One serial unit test checks matching actual C/Rust calls, UTF-8 with embedded NUL,
module/source mismatch, bad ABI metadata, file failures and denial before callback.
It also checks the intentional provider failure remains a located VM Host Fault.
The full scalar/layout conformance matrix belongs to the existing repository proof;
this example does not duplicate it or establish other-target compatibility.

## Native trust and lifetime

The selected descriptor variable outlives `Provider`; its metadata and code reside
in the linked image for process lifetime. There is no unload operation. Native code
is trusted process code. Version/size checks and source comparison cannot establish
pointer provenance, resource authority, time bounds or binary semantics.

Callbacks validate labels/counts/tags, initialize every scalar field, emit exactly
once synchronously on the invoking thread and retain no argument/context/emitter.
No panic or foreign exception may cross the ABI. All calls sharing mutable provider
state must be serialized across all wrappers; the one serial test follows this rule.
Scalar reply text is copied during emission while storage is still live.

Offline LSP selection/reload of this `api.fipi` needs no binary or callback and does
not authorize the host to run one. This example defines no resource wire format,
live schema, async scheduling, native/LLVM provider execution or dynamic loading.
Those remain separate contracts and release decisions.
