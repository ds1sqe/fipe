# tree-sitter-fipe

A [tree-sitter](https://tree-sitter.github.io/) grammar for Fipe, with
highlight, fold, indent, locals and injection queries. It mirrors
`Documentation/spec/01-lexical.ebnf` and `02-syntax.ebnf` in this
repository; those chapters are normative, and the language's own parser
(the `fipe` crate) is the oracle the tests compare against.

The crate does not depend on this package. The package uses the crate
only in its Rust tests, by path.

## Layout

| Path | What |
| --- | --- |
| `grammar.js` | the grammar; each conflict and precedence names its syntax rule |
| `src/scanner.c` | the external scanner: newlines, line joins, comments and docs, quotes, pipes, and word classification |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json` | generated by `tree-sitter generate` (CLI 0.26.9), committed |
| `queries/*.scm` | queries in nvim-treesitter capture names |
| `editors/helix/` | a `languages.toml` stanza and the queries in Helix names, derived by `scripts/queries.py` |
| `editors/nvim/` | a Neovim snippet and the headless smoke |
| `test/corpus/`, `test/highlight/` | `tree-sitter test` cases and capture assertions |
| `tests/lexical.rs`, `tests/oracle.rs` | the comparison with `fipe::lex` and `fipe::parse` |
| `scripts/check.sh` | every check of the package |

## Neovim

With nvim-treesitter, copy `editors/nvim/fipe.lua` into your config,
set `revision` to a commit of this repository, and run `:TSInstall
fipe`. It registers the `fipe` filetype and the parser for both the
`main` and the `master` branch of nvim-treesitter. On `main` the
queries are installed with the parser. On `master`, put them in your
runtimepath yourself:

```sh
mkdir -p ~/.config/nvim/queries
ln -s /path/to/fipe/tools/tree-sitter/queries ~/.config/nvim/queries/fipe
```

Without nvim-treesitter, Neovim's built-in tree-sitter support is
enough for highlights and folds: build the parser with `tree-sitter
build -o fipe.so`, then `vim.treesitter.language.add('fipe', { path =
'/path/to/fipe.so' })`, the runtimepath link above, and
`vim.treesitter.start()` in a `fipe` buffer. Indents need
nvim-treesitter's indent module.

## Helix

Add the stanza in `editors/helix/languages.toml` to
`~/.config/helix/languages.toml`, set `rev` to a commit of this
repository, run `hx --grammar fetch` and `hx --grammar build`, and copy
`editors/helix/queries/fipe/` to `~/.config/helix/runtime/queries/fipe/`.
Helix gives an earlier highlight pattern priority where Neovim gives a
later one, so its copy lists the same patterns in reverse order; edit
`queries/` and run `python3 scripts/queries.py`, never the copy.

## Checks

```sh
scripts/check.sh
```

It reproduces `src/` with `tree-sitter generate`, runs `tree-sitter
test`, parses the language's corpus files with no error node, checks
the Helix copies are current, builds the scanner with `-Wall -Wextra
-Werror -pedantic`, runs the binding's tests (`FIPE_ROOT` points at the
repository; the script sets it), clippy and docs, and the Neovim smoke
when `nvim` is installed. It needs no network.

## Differences from the crate's parser

The grammar and the crate agree on every source the crate accepts: same
named nodes, same kinds, same byte spans. They differ where the
comparison does not look, or where tree-sitter cannot say what the
crate says:

- The tree is concrete: punctuation, `pub` and comments are anonymous
  or extra, newlines hidden. Named nodes are compared by kind and span,
  names by text, pipes and arithmetic by operator span; nesting
  direction is not asserted.
- The crate returns no tree on an error; tree-sitter always returns one,
  with `ERROR` and `MISSING` nodes and its own recovery. For a source
  the crate rejects, only an error node near the crate's first
  diagnostic is asserted, on the line of the last token before it.
- Value rules stay the crate's: integer ranges, the 64-frame nesting
  limit and the expression depth limit are not enforced by the
  grammar.

Accepted by the grammar and rejected by the crate (proposed as
legitimate; awaiting the language owner's acceptance):

- no space before an argument: `Re"x"` parses;
- a doc comment with no owner, and `##!` after an entry;
- `[ !x]` with a space is a list holding a negation, where the crate
  reads an outcome;
- in a flag's value the `=` must touch the flag, but the value need not
  touch the `=`;
- in `"a"i\` followed by a line break and `x`, the crate takes `i` as
  the quote's suffix; the grammar ends the quote before `i`, which is
  then a name of its own.
